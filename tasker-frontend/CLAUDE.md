# CLAUDE.md — `tasker-frontend/`

Conventions for the React SPA. Repo-wide guidance lives in the root `CLAUDE.md`; environment
variables are catalogued in `docs/CONFIGURATION.md`.

- **Keep the anonymous first paint small.** `App.tsx` is a thin route shell: `AuthContext`, `LoginPage` and `AppFooter` are the only eager imports. The whole signed-in surface lives in `Board.tsx` and every other route is a `React.lazy` chunk, because the landing page is what a cold visitor (and every PageSpeed/crawler run) downloads — before the split it carried drag-and-drop, all the modals, the markdown renderer and the policy texts, and the mobile FCP/LCP showed it. New signed-in UI belongs in `Board.tsx` or a chunk it pulls in; a new route goes behind `Lazy` unless it is genuinely part of the anonymous entry path. Watch the `dist/` chunk list after a build — a new eager import in `App.tsx` shows up as growth in the entry chunk.
- **Web fonts are fully self-hosted, not linked.** `src/fonts.css` (generated by `tools/refresh-google-fonts.sh`, imported at the top of `src/index.css`) holds the `@font-face` declarations, and the woff2 files themselves live in `src/assets/fonts/` (also generated by that script) — `index.html` has no `<link>`/`preconnect` to `fonts.googleapis.com`/`fonts.gstatic.com` at all. Same-origin removes a render-blocking third-origin round trip and a per-visitor request to Google on every page load; the ops-repo CSP (`itayp_dev/ansible/group_vars/all/main.yml`, `tasks` service) has no googleapis/gstatic allowance to match. Do not reinstate a `<link href="fonts.googleapis.com/css2?…">` or point `font-src` back at gstatic. Adding a family or weight means editing `FAMILIES` in the script and re-running it, not hand-editing `fonts.css` or `assets/fonts/`.
- **Static content pages** (`/terms`, `/privacy`, `/about`, `/faq`) are English-only markdown files in `src/auth/` imported with `?raw` and rendered through the shared `PolicyPage` shell; `{{SUPPORT_EMAIL}}` is substituted at render time. Adding one means: the markdown file, an export in `PolicyPage.tsx`, a route in `App.tsx`, the path in `SpaForwardController` (+ its test), a `<url>` in `static/sitemap.xml`, a line in `static/llms.txt`, a link in `components/AppFooter.tsx` (the site-wide footer, rendered once below `<Routes>` so it reaches signed-in and signed-out views alike), and `policyPage.*Title` / `footer.*` keys in **all four** locale catalogs.
- **Styling: co-located CSS Modules for component-specific styles.** New components add a sibling `Foo.module.css` and import it as `import styles from './Foo.module.css'`; reference classes via `styles.title` / `styles.demoBtn`. Use camelCase keys. `src/index.css` is reserved for design tokens (CSS custom properties), base element styles, and genuinely shared utilities (`.link-btn`, etc.) — don't add new component-specific rules there. See `auth/LoginPage.module.css` and `auth/PolicyPage.module.css` for the pattern.
- Auth-aware shell in `src/App.tsx`: `AuthProvider` (in `src/auth/AuthContext.tsx`) runs `GET /api/auth/me` on mount. `LoginPage` offers Telegram (an outlined button that navigates to the OIDC redirect flow at `/api/auth/telegram/start`), passwordless email (inline form → magic link), a sandbox/demo button, a Google button (stubbed "Soon"), and a dev-login button gated on `import.meta.env.DEV`; it surfaces `?telegramLogin=failed|unavailable` callback notices (auto-opening the modal). `SettingsModal` has a "Connected accounts" section (`ConnectedAccounts.tsx`) to link Telegram (navigates to `/api/auth/telegram/link/start`, surfaces `?telegramLink=…`) / unlink methods. The display name degrades gracefully for channel-less users (`UserMenu`: display name → telegram → email → "Account").
- `src/api.ts` wraps `fetch` with `credentials: 'include'`, echoes the XSRF cookie as `X-XSRF-TOKEN` on mutating requests, and dispatches an `auth:unauthenticated` event on 401 so `AuthContext` can flip to the login page.
